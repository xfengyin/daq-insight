# DAQ Insight 架构文档

> 版本：0.1（随 MVP P0 演进）
> 状态：与当前代码基线同步（T1–T8 已完成，T9–T12 UI 进行中，T13 集成测试/打包/文档）

## 1. 概述

DAQ Insight 是面向 Keysight DAQ970A / 34970A 数据采集仪导出文件的智能处理桌面工具。
用户在 Windows 桌面导入 CSV/TSV/TXT 导出文件后，工具自动完成**分列、类型识别、清洗、
统计分析与可视化**，并可导出 CSV / Excel / PNG 结果。

- 技术栈：Electron（主进程 + preload）+ React + TypeScript + ECharts + Vite（electron-vite）
- 测试：Vitest（Node 环境单元/集成测试）
- 解析依赖：papaparse（CSV 切分）、iconv-lite（GBK 等编码）、jschardet（编码侦测）、xlsx（Excel 导出）
- 界面语言：中文；平台目标：Windows（x64，NSIS 打包）

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  渲染进程 src/（React + ECharts，中文 UI）                     │
│  ┌───────────┐ ┌──────────┐ ┌───────────┐ ┌──────────────┐  │
│  │ 导入/检测  │ │ 通道校正  │ │ 预览表    │ │ 波形/统计面板 │  │
│  └─────┬─────┘ └────┬─────┘ └─────┬─────┘ └──────┬───────┘  │
│        └─────────────┴─────┐ ┌────┴──────────────┘          │
│                window.daqAPI（src/shared/ipc.ts 定义）        │
└────────────────────────────┼────────────────────────────────┘
                             │ contextBridge（结构化克隆）
┌────────────────────────────┼────────────────────────────────┐
│  preload electron/preload.ts┘（通道名与类型见 src/shared/ipc.ts）│
│  主进程 electron/main.ts（ipcMain.handle 注册 IPC handler）    │
│        │ 调用                                            │
│        ▼                                                  │
│  核心引擎 core/（纯逻辑，无 UI 依赖，可独立测试）                │
│  models.ts（共享数据模型契约）                                 │
│  detection → parsing → identification → cleaning → analysis │
│  → export                                                    │
└─────────────────────────────────────────────────────────────┘
```

依赖方向：**渲染进程 → IPC（src/shared/ipc.ts）→ 主进程 → core/**；
core 内部只依赖 core/models.ts，不依赖 electron / react / src 任何模块，保证可单测。

## 3. 六阶段数据处理流水线（R1 设计）

核心引擎按以下流水线处理一份导入文件，阶段间通过 core/models.ts 的类型衔接：

```
文件路径
  │  ① 格式侦察（detection）
  ▼
DetectionResult{ raw(编码/分隔符/表头行数/小数风格/布局/preamble), confidence, notes }
  │  ② 表头解析（parsing/header）+ ③ 类型识别（identification）
  ▼
ChannelDef[]（通道列索引/名称/通道号/测量类型/单位/isTimestamp）
  │  ④ 数据解析与标准化（parsing/parser）
  ▼
StandardizedData{ metadata, channels[], timeIndex, statistics }
  │  ⑤ 数据清洗（cleaning，可选，用户配置）
  ▼
StandardizedData（缺失插值/异常标记/时间戳去重）
  │  ⑥ 统计分析（analysis）
  ▼
AnalysisResult{ channelStats, durationMs, sampleRateHz }
  │
  ├──→ 可视化：getChartSeries（降采样）→ ECharts
  └──→ 导出：export（CSV/Excel）
```

### 3.1 ① 格式侦察 — core/detection/

| 文件 | 职责 |
|---|---|
| encoding.ts | 编码侦测（UTF-8/GBK/Big5/UTF-16 等，jschardet 兜底） |
| sniffer.ts | 分隔符、表头行数、小数点风格、数据行判定启发式 |
| detector.ts | 组合以上子检测，读文件头 ≤64KB / 前 100 行，输出 DetectionResult；同时判定布局（wide/long/scan）与 preamble 元信息行数 |

入口：detectFile(path): Promise<DetectionResult>（IPC：engine:detectFile）

### 3.2 ② 表头解析 — core/parsing/header.ts

将完整行矩阵（preamble + 表头 + 数据）按表头行数切分、逐列合并多行表头，
对每列调用 identification 的 identifyChannel 生成 ChannelDef。

三种布局（LayoutType）：
- **wide（宽表）**：Time,CH101,CH102,...，时间戳列标记 isTimestamp
- **long（长格式）**：Channel,Reading,Unit,Timestamp，通道定义从数据行的 Channel 列提取唯一通道号、Unit 列提取单位（需 pivot）
- **scan（扫描格式）**：首列扫描序号（Scan #）跳过，其余按宽表处理

入口：parseHeader(rows, headerRows, opts?): ChannelDef[]（IPC：engine:parseHeader）

### 3.3 ③ 类型识别 — core/identification/

| 文件 | 职责 |
|---|---|
| patterns.ts | 模式库：通道号正则、测量类型/单位模式表、单位→类型兜底表 |
| identifier.ts | cleanCell / extractChannelNumber / matchMeasurementType / matchUnit / unitToMeasurementType / isTimestampHeader / inferLayout / identifyChannel |

识别顺序：通道号模式 → 类型模式表 → 单位兜底表 → 样本数值特征兜底（识别不出为 UNKNOWN）。
支持的测量类型见 core/models.ts 的 MeasurementType（DCV/ACV/DCI/ACI/TC/RTD/2W/4W 电阻/频率/周期）。

### 3.4 ④ 数据解析与标准化 — core/parsing/

| 文件 | 职责 |
|---|---|
| converter.ts | parseValue（含小数风格 '.'/','、科学计数法、OVER/UNDER/OPEN/SHORT/空 → NaN + 质量标记）、parseTimestamp / convertTimestamps（多格式时间戳→Unix 毫秒） |
| parser.ts | readText（按检测编码解码）、loadCsvText（papaparse 切分）、loadCsv、parseFile（转换 → 时间轴 → StandardizedData） |

入口：parseFile(path, raw, channels): Promise<StandardizedData>（IPC：engine:parseFile）

特殊值约定（与真实 DAQ970A 对齐）：
OVER/UNDER → QualityFlag.OVER_RANGE（NaN，不参与统计）、OPEN/SHORT/Sensor Error → INVALID、
空字段 → MISSING；+9.9E37 超量程数值 → OVER_RANGE。

### 3.5 ⑤ 数据清洗 — core/cleaning/cleaner.ts

clean(data, opts): StandardizedData（IPC：engine:clean），CleanOptions：
- missing：interpolate（线性插值）/ ffill（前向填充）/ drop（删除行）
- outlier：none / iqr / zscore（Z-score 阈值默认 3.5，标记为 INVALID）
- dedupeTimestamps：重复时间戳去重（保留首条）

### 3.6 ⑥ 统计分析 — core/analysis/

| 文件 | 职责 |
|---|---|
| statistics.ts | computeChannelStats：均值/标准差/极值/RMS/有效数/缺失数/超量程数（忽略 NaN 与非 GOOD 点） |
| engine.ts | analyze：逐通道统计 + 整体摘要（时间跨度、采样率，由时间索引中位间隔推算） |

入口：analyze(data): AnalysisResult（IPC：engine:analyze）

### 3.7 导出与可视化

- core/export/exporter.ts：exportCsv（UTF-8 BOM，时间戳 iso/raw、缺失占位符可配）、
  exportExcel（SheetJS 三表）→ ExportOutcome{path, bytes, rows}（IPC：engine:export）
- 可视化在渲染进程完成：engine:getChartSeries（通道子序列 + 最大点数降采样）→ ECharts；
  engine:getPreview（预览表 ≤ maxRows 行，NaN→null 显示 "--"）

## 4. 核心数据模型（core/models.ts — 共享契约）

| 类型 | 说明 |
|---|---|
| FileFormat | csv / tsv / txt / xlsx |
| MeasurementType | dc_voltage / ac_voltage / dc_current / ac_current / temperature_tc / temperature_rtd / resistance_2w / resistance_4w / frequency / period / unknown |
| QualityFlag | good / missing / invalid / over_range |
| LayoutType | wide / long / scan |
| RawFile | 原始文件描述：path、format、encoding、delimiter、decimal、headerRows、sampleRows、layout?、preambleLines? |
| ChannelDef | 通道定义：index、name、channelNumber?、measurementType、unit?、isTimestamp、isValid |
| ChannelData | values[] + timestamps[]? + quality[]（与 values 等长） |
| StandardizedData | metadata + channels[] + timeIndex? + statistics? |
| DetectionResult | raw + confidence{encoding,delimiter,headerRows} + notes[] |
| ChannelStats | mean/std/min/max/rms/count/missingCount/overRangeCount |

**契约原则**：任何修改必须向后兼容；新增字段使用可选属性；修改时在任务输出中说明改动点。

## 5. IPC 通道表（src/shared/ipc.ts — 唯一事实来源）

| 通道名 | 方向 | 请求 | 响应 | 说明 |
|---|---|---|---|---|
| dialog:openFile | renderer→main | — | OpenFileResult | 打开文件对话框（csv/txt/tsv） |
| dialog:saveFile | renderer→main | defaultPath?, filters? | SaveFileResult | 保存文件对话框 |
| engine:detectFile | renderer→main | DetectFileRequest{path} | DetectionResult | ①格式侦察 |
| engine:parseHeader | renderer→main | ParseHeaderRequest{rows,headerRows,layout?,preambleLines?} | ChannelDef[] | ②③表头+类型识别 |
| engine:parseFile | renderer→main | ParseFileRequest{path,raw,channels} | StandardizedData | ④解析与标准化 |
| engine:clean | renderer→main | CleanRequest{data,options} | StandardizedData | ⑤清洗 |
| engine:analyze | renderer→main | AnalyzeRequest{data} | AnalysisResult | ⑥统计分析 |
| engine:export | renderer→main | ExportRequest{data,format,path} | ExportResult | 导出 CSV/Excel |
| engine:getPreview | renderer→main | GetPreviewRequest{data,maxRows?} | PreviewData | 预览表 |
| engine:getChartSeries | renderer→main | GetChartSeriesRequest{data,channelIndexes,maxPoints?} | ChartSeries[] | 图表序列（降采样） |
| menu:event | main→renderer | — | MenuAction | 主进程菜单事件推送（webContents.send） |

约定：handler 一律 ipcMain.handle（invoke 风格）；错误统一 throw，preload 捕获后 reject。
渲染进程通过 window.daqAPI（DaqApi 接口，preload contextBridge 注入）调用。

## 6. 典型端到端时序

1. 用户拖拽/选择文件 → daqAPI.getPathForFile(file) 或 openFileDialog()
2. detectFile(path) → DetectionResult（编码/分隔符/表头行数/布局/preamble）
3. loadCsv(path, raw)（主进程侧内部）→ 行矩阵 → parseHeader(rows, headerRows, {layout, preambleLines}) → ChannelDef[]
4. UI 展示检测结果与通道定义，用户可校正（表头行数/布局/类型）
5. parseFile(path, raw, channels) → StandardizedData
6. 可选 clean(data, options) → 清洗后数据
7. analyze(data) → AnalysisResult；getChartSeries + getPreview 供 UI 展示
8. exportData(data, 'csv'|'xlsx', path) → 导出文件

## 7. 扩展点

| 扩展需求 | 修改位置 | 说明 |
|---|---|---|
| 新增测量类型 | core/identification/patterns.ts + core/models.ts MeasurementType | 类型模式表 + 单位→类型表 + 枚举（向后兼容） |
| 新增分隔符/编码 | core/detection/sniffer.ts、encoding.ts | 分隔符候选表、编码表 |
| 新增真实导出格式（如 PICC/SCPI 变体） | core/detection/detector.ts（布局判定）、core/parsing/header.ts | 先补 tests/fixtures 样本 + .meta.json 再实现 |
| 新增清洗策略 | core/cleaning/cleaner.ts CleanOptions | missing/outlier 策略分支 |
| 新增导出格式 | core/export/exporter.ts + src/shared/ipc.ts ExportFormat | 追加导出函数与 IPC 类型 |
| 图表降采样算法 | engine:getChartSeries 实现（主进程或 core） | 大数据量性能 |
| 新 UI 功能 | src/ + src/shared/ipc.ts + electron/ | 新增 IPC 通道名常量与类型 |

扩展原则：**先加样本与断言（tests/fixtures + .meta.json + 测试），再实现**；
IPC 通道名/类型改动必须同步 src/shared/ipc.ts 与 preload/主进程注册处。

## 8. 测试策略

- 单元测试：tests/*.test.ts（detection/parser/identification/analysis/export/models），
  以 tests/fixtures/samples/ 真实样本 + .meta.json 为断言基准
- 集成测试：tests/integration/pipeline.test.ts（六阶段全链路，T13 逐步补齐样本矩阵）
- 样本生成：npm run gen:fixtures（确定性，重复生成 sha256 一致）
- 类型检查：npm run typecheck；打包：npm run build:win（NSIS）
